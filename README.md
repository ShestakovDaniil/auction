# Auction Lab

Готовый учебный веб-проект аукционной площадки на **FastAPI + SQLAlchemy + MariaDB/MySQL**.

В исправленной версии есть:

- регистрация покупателей и продавцов;
- вход по логину или email;
- JWT-сессия в HttpOnly cookie;
- личный кабинет покупателя и продавца;
- создание лотов;
- отдельный запуск аукциона для созданного лота;
- активные, ожидающие и завершённые аукционы;
- ставки покупателей с защитой от одновременных конфликтующих ставок;
- запрет продавцу ставить на собственный лот;
- автоматическое обновление статуса по времени начала/окончания;
- ручное завершение торгов владельцем лота;
- определение победителя по максимальной ставке;
- каталог с поиском, фильтром и нормальной пагинацией;
- JSON API и Swagger UI;
- health-check подключения к MariaDB/MySQL.

## Что было исправлено

Старая версия проекта содержала код сразу от двух разных моделей данных: часть приложения ожидала `Bid`, `User.name`, `Auction.starts_at`, а реально подключённые ORM-модели имели `Sale`, `User.username`, `Auction.start_time`. Из-за этого некоторые экраны и API были несовместимы друг с другом.

Также при создании JWT числовой `user.id` записывался в claim `sub`. В актуальных JWT-библиотеках `sub` должен быть строкой; из-за этого cookie мог существовать, но пользователь всё равно получал `401` при открытии личного кабинета.

Теперь проект использует одну согласованную модель. `sub` хранится строкой, а при чтении безопасно преобразуется обратно в integer ID.

Для совместимости со старой БД таблица `sales`, которая в предыдущем проекте фактически использовалась для ставок, сохранена. В коде она называется `Bid`, поэтому существующие ставки не требуют переноса только из-за исправления названия сущности.

## Требования

- Python 3.11+
- MariaDB 10.6+ или MySQL 8+
- InnoDB

Проект намеренно настроен только на MariaDB/MySQL через `PyMySQL`.

## 1. Подготовка базы

Пример для MariaDB/MySQL:

```sql
CREATE DATABASE auction_lab
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

CREATE USER 'auction_app'@'127.0.0.1'
    IDENTIFIED BY 'change_me';

GRANT ALL PRIVILEGES ON auction_lab.*
    TO 'auction_app'@'127.0.0.1';

FLUSH PRIVILEGES;
```

Если приложение подключается к БД с другого хоста, скорректируйте host в `CREATE USER` и `DATABASE_URL`.

## 2. Установка

```bash
python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Зависимости:

```bash
pip install -r requirements.txt
```

## 3. `.env`

Скопируйте пример:

```bash
cp .env.example .env
```

Основные параметры:

```env
APP_NAME=Auction Lab
APP_ENV=development
APP_HOST=127.0.0.1
APP_PORT=8000

DATABASE_URL=mysql+pymysql://auction_app:change_me@127.0.0.1:3306/auction_lab?charset=utf8mb4
AUTO_CREATE_TABLES=true

APP_SECRET_KEY=replace-with-a-long-random-secret
ACCESS_TOKEN_EXPIRE_MINUTES=1440
COOKIE_SECURE=false
MIN_BID_INCREMENT=1.00
CATALOG_PAGE_SIZE=9
```

Для production используйте длинный случайный `APP_SECRET_KEY` и HTTPS с `COOKIE_SECURE=true`.

## 4. Проверка MariaDB/MySQL

```bash
python scripts/check_db.py
```

Ожидаемый результат:

```text
Database connection OK
Server version: ...
```

## 5. Запуск

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте:

- `http://127.0.0.1:8000/` — веб-интерфейс;
- `http://127.0.0.1:8000/dashboard` — личный кабинет;
- `http://127.0.0.1:8000/docs` — Swagger UI;
- `http://127.0.0.1:8000/health` — проверка приложения и БД.

При `AUTO_CREATE_TABLES=true` отсутствующие таблицы создаются автоматически.

## Демонстрационные данные

Только для пустой тестовой БД:

```bash
python scripts/seed.py
```

Будут созданы:

```text
seller_demo / seller123
buyer_demo  / buyer123
```

а также два лота, два аукциона и одна тестовая ставка.

## Основной сценарий продавца

1. Зарегистрироваться как **Продавец**.
2. Открыть личный кабинет.
3. Нажать **Новый лот**.
4. Указать название, описание и стартовую цену.
5. После сохранения выбрать время начала и окончания аукциона.
6. Опубликовать аукцион.
7. Смотреть ставки на странице торгов.
8. При необходимости завершить аукцион вручную.

## Основной сценарий покупателя

1. Зарегистрироваться как **Покупатель**.
2. Открыть активный аукцион из каталога.
3. Ввести ставку не ниже показанного минимального значения.
4. Отслеживать свои ставки в личном кабинете.
5. После завершения аукциона на странице торгов отображается победитель.

## Совместимость со старой базой

Исправленная версия сохраняет названия и ключевые колонки существующих таблиц:

- `users`
- `lots`
- `auctions`
- `sales` (история ставок)

Поэтому БД, созданная непосредственно предыдущей версией из присланного проекта, не требует удаления только ради исправления авторизации и интерфейса.

Если вы ранее вручную меняли таблицы или использовали другую, более старую схему из документации, сначала сделайте backup БД и сравните структуру таблиц.
