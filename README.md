# Auction Lab — лабораторная работа №3

Веб-приложение электронных аукционов на **Python / FastAPI / SQLAlchemy / MariaDB**.
Содержит исходные веб-страницы, JSON API, регистрацию покупателей и продавцов, лоты, аукционы и ставки.
Лабораторная №3 добавляет единые команды, модульные и интеграционные тесты, Ruff, Bandit,
миграции Alembic, резервные копии и новую функцию **избранных лотов**.

## Установка (Debian 13 / Linux)

Требуются Python 3.11+, `make`, `python3-venv`, клиент `mariadb-client` и работающий
сервер MariaDB/MySQL. Сервер БД может работать на этой же машине или отдельно (например,
второй сервер из лабораторной №2). **Для тестов необходима отдельная БД**.

На Debian установите системные инструменты:

```bash
sudo apt update
sudo apt install -y python3 python3-venv make mariadb-client
```

Создайте на сервере две базы данных и предоставьте пользователю права только на них.
Пример для приложения, подключающегося с машины в сети `172.16.10.0/24`:

```sql
CREATE DATABASE auction_lab CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE auction_lab_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'auction_app'@'172.16.10.%' IDENTIFIED BY 'REPLACE_WITH_STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON auction_lab.* TO 'auction_app'@'172.16.10.%';
GRANT ALL PRIVILEGES ON auction_lab_test.* TO 'auction_app'@'172.16.10.%';
```

Если приложение и СУБД расположены на одном компьютере, используйте пользователя
`'auction_app'@'127.0.0.1'` и подключение к `127.0.0.1:3306`. Для отдельного сервера
укажите его действующий IP-адрес/порт, настройте разрешение подключения и сетевые правила.
Учётные данные в SQL-примере необходимо заменить. Если пользователь/базы уже существуют,
повторное создание не требуется — достаточно проверить права.

Запустите в корне проекта:

```bash
make setup  # установит зависимости, предложит параметры БД, создаст .env и применит миграции
make verify # запустит все обязательные проверки, включая тесты на отдельной MariaDB
make run    # запустит веб-приложение
```

`make setup` создаёт `.venv`, устанавливает зависимости, вызывает `scripts/setup_env.py`
для создания `.env` (если конфигурации ещё нет), форматирует исходники, проверяет соединение
с основной БД и применяет миграции. Тестовая БД должна существовать до `make verify`.
Если предпочитаете заполнить конфигурацию вручную, скопируйте `.env.example` в `.env`,
поменяйте параметры и создайте уникальный `APP_SECRET_KEY`.

Важные параметры:

- `DATABASE_URL=mysql+pymysql://...:3306/auction_lab?charset=utf8mb4` — рабочая БД;
- `TEST_DATABASE_URL=mysql+pymysql://...:3306/auction_lab_test?charset=utf8mb4` — тестовая БД;
- `APP_SECRET_KEY` — случайный секрет длиной от 32 символов;
- `AUTO_CREATE_TABLES=false` — управлением схемой занимается Alembic.

**Не запускайте тесты на рабочей БД.** Интеграционные тесты удаляют и создают таблицы
только в отдельной БД, имя которой должно оканчиваться на `_test`.
`make verify` также проверяет, что на рабочую БД уже применены все ревизии.

Swagger UI: `http://127.0.0.1:8000/docs`, health: `/health`.

## Унифицированные команды

| Команда | Назначение |
| --- | --- |
| `make setup` | Первая настройка Python, `.env`, базы данных и миграций |
| `make run` | Локальный Uvicorn на порту 8000 |
| `make test` | Все тесты, включая реальную MariaDB; JUnit и coverage XML/HTML; порог покрытия 40% |
| `make test-local` | Только локальные unit/SQLite-тесты, **не замена verify** |
| `make quality` | `ruff format --check`, `ruff check`, Bandit SAST |
| `make format` | Исправить форматирование при разработке |
| `make migrate` | Применить миграции 0001 → 0002 → 0003 |
| `make backup` | SQL-снимок БД в `backups/*.sql.gz`, права 0600 |
| `make restore` | Загрузить SQL-снимок в БД, с обязательным подтверждением |
| `make mutation-check` | Убедиться, что тесты обнаруживают подмену шага ставки |
| `make verify` | quality → test → mutation-check → проверка ревизии БД → compileall |

`make verify` **не** подавляет ошибки и завершается неуспешно при любой проблеме.
`TEST_DATABASE_URL` должен вести к отдельной базе с именем `*_test`;
`make test` на ней может удалять таблицы. Никогда не подставляйте сюда основную базу.

## Миграции и совместимость

* `0001_core_schema`: users, lots, auctions, sales (историческая таблица ставок).
* `0002_lot_condition`: поле `lots.condition` со значением по умолчанию `used` для старых строк.
* `0003_favorite_lots`: отдельная таблица избранного с ограничением `UNIQUE(user_id, lot_id)`.

На **чистой** БД создаются все таблицы. Если уже существуют исходные четыре таблицы без
`alembic_version`, `make migrate` проверяет обязательные колонки, помечает схему как `0001`
и обновляет ее до `0003` без уничтожения строк. Если схема неполная или уже изменена
неоднозначным образом, операция останавливается для ручного анализа.
`AUTO_CREATE_TABLES=false` обязателен: схему создаёт только Alembic.

## Новое требование / функциональное изменение

Авторизованный пользователь может сохранять доступные лоты в избранное:

* `PUT /api/lots/{lot_id}/favorite` — добавить (повторный запрос идемпотентен);
* `DELETE /api/lots/{lot_id}/favorite` — удалить (повторный запрос идемпотентен);
* `GET /api/users/me/favorites` — только собственные доступные лоты.

Изменяющие запросы защищены CSRF и авторизацией; недоступные черновики не раскрываются.

## Снимок и восстановление

```bash
make backup
# на выходе: backups/auction_lab-20261104T095200Z.sql.gz
# затем можно намеренно изменить тестовые данные и восстановить:
BACKUP_FILE=backups/ИМЯ_ФАЙЛА.sql.gz CONFIRM_RESTORE=auction_lab make restore
```

Внимание: `make restore` перезаписывает данные указанной БД. Выполняйте на отдельной
учебной копии после проверки файла, имени БД и конфигурации `.env`.
Дамп делается средствами `mariadb-dump`/`mysqldump` с `--single-transaction`.
